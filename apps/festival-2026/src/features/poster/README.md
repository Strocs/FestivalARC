# Edit the static ARC 2026 poster

The homepage is built as Astro HTML with one copy of each artist name. TypeScript computes logical slots at build time; CSS selects the desktop, tablet or mobile placement without client JavaScript.

## Quick path

1. Edit `lineup.ts` for names, stable IDs and company associations. Do not invent activities, dates or venues.
2. Edit `poster.ts` for the module proportions, information footprints and decorative sequence. Coordinates start at zero.
3. Run `pnpm --filter festival-2026 test`, then `pnpm build`. Browser checks use `pnpm exec playwright test tests/e2e/arc2026-document.spec.ts tests/e2e/arc2026-static-grid.spec.ts tests/e2e/arc2026-pattern-seams.spec.ts tests/e2e/festival-navbar.spec.ts` after the root build.

## Layout rules

| Range | Columns | Artist starts |
| --- | --- | --- |
| Desktop, `xl` / at least 1280px | 10 | Even rows: 0/4/8; odd rows: 2/6 |
| Tablet, `md` / 768–1279px | 6 | Even rows: 0/4; odd rows: 2 |
| Phone, below 768px | 3 | Column 0 on alternate rows, full width; two decorative rows after the hero |

Each name uses one row and two columns on tablet/desktop or all three columns on mobile. The cells directly underneath are reserved for future expansion, but currently display decorative motifs. Information reserves its complete footprint first; a blocked start is skipped, never moved to another column or used to restart row parity. The logical row count grows to accommodate the roster and its reservations; rendered row height follows the hybrid sizing rules below.

`calculatePosterLayout` is a pure function. An optional fourth argument supplies explicit artist anchors such as `{ id: 'nino-cohete', column: 0, row: 6 }`; invalid cadence, collisions, duplicate or unknown identities are rejected before rendering. The optional fifth argument, `artistStartRow`, sets the earliest artist row (zero by default). Mobile sets it to 4, leaving two complete decorative rows below its two-row hero. Do not modify positions with browser measurements.

The stepped desktop title uses two adjacent footprints. Phone/tablet information positions are authored separately. `slotSize` starts at 160×152 and defines the base module proportions; actual width follows available space.

## Decorative distribution

`selectPosterMotifs` chooses one shared sequence at Astro build time, considering desktop, tablet and mobile placements together. CSS only changes positions: each tile keeps the same SVG/use, without extra markup or client JavaScript. Geometry and roster ordering remain owned by `calculatePosterLayout`.

- **Shape families:** seven groups; opposite chevrons share a family, as do all three rosettes and both orbits. Matching families cannot share an edge in any layout. Diagonal repetitions receive a soft penalty.
- **Accent weights:** the eleven variants contain six magenta/rose-only, three cyan (lightning, cyan rosette/orbits) and two yellow (yellow rosette, sparks). Cumulative deficits favor that approximate 6:3:2 mix, not equal colored pixel areas or a rigid repeating sequence. Magenta remains predominant.
- **Soft balance:** recent and neighboring accent repetitions receive penalties; per-variant deficits keep individual designs in rotation. These preferences never override the edge rule. Catalog order breaks ties deterministically.

Run `pnpm --filter festival-2026 test src/features/poster/__tests__/poster-motif-distribution.test.ts` for responsive edge checks, prefix balance, color-gap bounds and unchanged shared-input behavior. Soft balance bounds describe the current roster/presets, not universal quotas for arbitrary future layouts.

## Hybrid sizing

Below `md`, explicit logical rows use content-sized tracks. Each full artist card retains a minimum footprint of three adjacent horizontal decorative slots: three columns wide and one geometric module high. The tiles retain their proportions, so their narrower width also reduces their height and the distance between artist rows without a separate height adjustment. Artist labels refit within that footprint rather than increasing its height for long or enlarged names; the full card must not collapse to the smaller interior label. The minimum is applied on the outer artist-slot wrapper, whose container is the poster rather than the nested artist container. Information blocks can also grow with wrapping text; the hero spans two natural rows. Decorative slots keep a 160/152 aspect ratio. From `md`, proportional module heights become track minimums, with content-aware growth when text needs more room; decorative slots no longer impose their own aspect ratio. Content wrappers use grid stretching rather than percentage child heights. Information text contributes its natural height; artist text is fitted to its reserved area without overflowing into adjacent rows. Placement, roster order and adjacent tile reservations use the same calculation in every range; there is no second mobile render or browser packing engine.

`--unit` converts artwork coordinates into a geometric module based on the poster's available width. Keep it for proportional grid-track minimums and the mobile artist-slot height minimum, not for font sizes, padding or margins. The wider-screen title uses 4/3 of its three-column hero width to reach the existing fourth-column spill footprint. An inherited custom property containing `cqw` resolves that unit at its consumer; reusing the poster's formula inside a smaller container would incorrectly scale the title width a second time. Intrinsic SVG dimensions and the page's maximum width do not need blanket clamps.

Title, date and information text retain bounded `clamp()` utilities and their own inline-size containers. Artist names instead use server-measured uppercase Poppins 900 advances from `poppins-black-metrics.json`; `artist-name.ts` computes each name's width in em without a runtime font parser. The label's font size is the smaller of the width fit and height fit, with no percentage target or arbitrary font-size ceiling. Artist spacing uses Tailwind's rem-based scale: the accent background is inset 1.5rem horizontally and 1rem vertically (1.5rem vertically from `md`), preserving the dark outer margin. Its size container reserves another 0.75rem horizontally and 0.5rem vertically as breathing room for the letters. The article and label need no padding; the insets alone define these spaces. The smaller mobile vertical inset leaves usable name space within the naturally shorter three-column module. Spacing grows with the root font size; enlarged spacing leaves less room for the automatically fitted letters and does not guarantee text-resize accessibility. For each possible line count, dynamic programming finds the word-boundary composition with the narrowest maximum line. The server calculates the aspect-ratio intervals where each composition gives the largest fitting font; CSS container queries select the winner using the real available width and height. Ties prefer fewer lines. Native aspect queries can quantize fractional dimensions near a switching boundary; rendered optimality and containment allow at most one CSS pixel of rounding. GEPE remains one line; compound names can wrap without increasing their slots. Names remain a single copy of selectable HTML and require no client JavaScript. Regenerate the committed metrics when changing Poppins 900; unsupported characters fail explicitly instead of silently using incorrect widths. `tests/e2e/arc2026-artist-sizing.spec.ts` checks actual label containment, maximum occupation in at least one dimension, and GEPE's larger size across breakpoint edges. Title text stays in normal flow and can wrap beyond its four authored groups when space or enlarged text requires it.

After a fresh root build, run `pnpm exec playwright test tests/e2e/arc2026-hybrid-sizing.spec.ts` in addition to the existing browser checks. It exercises fixed mobile artist footprints under root text enlargement, readable text, artist uniqueness, breakpoint edges and 200% root text sizing. Artist labels refit rather than guaranteeing that their font grows under text-only enlargement; this is the explicitly selected fixed-slot behavior, not a claim of WCAG text-resize compliance. Its halved CSS viewport case approximates zoom-induced reflow only: it is not native browser zoom, and `deviceScaleFactor` changes raster density rather than zoom. The same suite compares every full mobile artist card against three live adjacent decorative slots, without freezing pixel dimensions or label size. Passing rendered checks, not the sizing formulas alone, is the fit evidence. The artist-sizing suite also compares the rendered font against every candidate's mathematical maximum and checks that multiline names wrap when that permits larger text.

## Poster styling

The homepage composition in `pages/index.astro` and the five poster components (`ArtistName`, `PosterIntro`, `PosterInformation`, `PosterPattern`, and `PosterDefinitions`) use statically detectable Tailwind 4.1 utilities, with no authored static style blocks. `ArtistName` additionally emits server-generated font-fit container-query rules for its measured word compositions; presentation utilities remain Tailwind. Shared slot strings and the motif color map contain complete utility names, not interpolated fragments. Unused legacy styling classes are removed; `information-slot` and `pattern-slot` remain because browser tests consume them. Functional data attributes and shared navbar hooks are preserved.

`pages/index.astro` assigns runtime CSS variables from `calculatePosterLayout` and the existing presets. Utilities consume those values for grid placement and container-relative sizing. Responsive utilities are mobile-first: unprefixed styles define the phone layout, `md:` selects tablet from 48rem (768px), and `xl:` selects desktop from 80rem (1280px). The 1200–1279px range now intentionally uses the tablet layout, with no custom breakpoint overrides. Colors and fonts reuse the installed theme tokens. Intrinsic SVG geometry stays in the artwork, not in styling utilities.

Run `pnpm --filter festival-2026 test src/features/poster/__tests__/poster-grid.test.ts src/features/poster/__tests__/poster-motifs.test.ts` for layout-algorithm and stable tile checks. Tests protect functionality and the accepted decorative tile artwork, including raster seams; they do not freeze typography, page composition, utility classes or source structure. The shell and infrastructure utility boundary is described below.

## Shell and infrastructure styling

`Header` consumes `@festivalarc/ui/FestivalNavbar.astro` on the homepage and existing detail routes. Its minimum height follows ARC 2024 (72px); logo/date are required, location/links/CTA are optional, and Ediciones lists every other edition. The confirmed header copy is “28 y 29 de noviembre” (2026) and “Plaza de Armas de La Serena”. Header colors are inherited CSS tokens assigned using Tailwind utilities. See `packages/ui/README.md` for slots, tokens, public styling hooks and mobile dialog behavior. Historical apps are not migrated; the old `PreviousEditions` source is retained but no longer used by Header.

`features/program/ArtistDetail.astro` retains its existing static presentation and standard `md:` cutoff. The unused overlay, selection store and enhancement/motion scripts have been removed; direct artist routes remain available.

`styles/global.css` retains the Tailwind import and existing color/font theme tokens, and explicitly scans `packages/ui/src` with `@source`. The single `layouts/Layout.astro` delivers both local fonts and all metadata. Layout utilities carry page sizing, body typography/color and low-specificity heading/link defaults. The `:where()` variants deliberately allow existing element utilities to override those defaults, including the edition links' outline-style override. Existing layout, footer and poster utilities are not rewritten.

Run `pnpm --filter festival-2026 test` and `pnpm build`, then the browser checks in the quick path. Navbar tests cover required/optional slots, accessible content, mobile keyboard/focus/resize behavior, edition links and public customization. The homepage has no artist-overlay lifecycle.

## Rendering and boundaries

- `pages/index.astro` owns page composition and responsive geometry; `ArtistName.astro` only renders a name and its decoration. Names remain selectable HTML using the existing local Poppins 900 delivery.
- `PosterPattern.astro` bleeds decorative SVGs by 0.5 CSS pixels per side to cover subpixel seams. Grid cells keep their original dimensions; curves and diagonals retain normal antialiasing. Do not clip this bleed at each cell or combine it with global `crispEdges`. Regression check: `pnpm exec playwright test tests/e2e/arc2026-pattern-seams.spec.ts` after the root build.
- `PosterIntro.astro` renders the title as selectable HTML in four authored groups that may wrap further: “EL ARTE / DE HABITAR / LA / CIUDAD”, using local Poppins Black 900 as an approximation of the supplied artwork, not an identification of its original typeface. Tight tracking, compact leading, foreground white, cyan (`#5ce1e6`) and magenta (`#e50070`) preserve the approved title appearance without loading `LOGO_HERO.png`. Below `md`, the longest line nearly fills the full two-column hero width and its height grows naturally with the text; a full-width wrapper alone is not sufficient. From `md`, the heading explicitly reaches four columns using 4/3 of the hero width, but only “DE HABITAR” uses that extra measure; the other groups stay within the three-column hero. Independent rem-plus-local-container clamps keep dates smaller than the title, with a spacing-scale gap between them. Normal widths retain the four authored lines; enlarged text may wrap within groups, including long words, rather than clipping or painting over adjacent slots. Visible dates use the confirmed festival dates, 28–29 November 2026; they do not assign artists to days.

Title-specific browser coverage: after the root build, run `pnpm exec playwright test tests/e2e/arc2026-poster-title.spec.ts`. It checks accessible copy, loaded Poppins 900, normal four-line grouping, relative date hierarchy, near-full mobile text measure, reserved spill containment, clipping and artist-text separation at 320, 390, 767, 768, 1024, 1279, 1280, 1440 and 1920px, both normally and with 200% root text. This is text enlargement, not native browser zoom. Title tuning must not change artist-card geometry or the existing functional test policy.
- `poster-motifs.svg` retains the accepted design export, except for `lightning`: its four cyan triangles use straight vector edges rather than the source JPEG's traced pixel steps. Preserve its magenta background, cyan fill and alternating arrangement.
- The homepage and artist-detail routes use `layouts/Layout.astro` for the document shell, metadata, fonts, shared Header and Footer.
- The demo program and direct demonstration artist route remain separate. No filters, expansion, client store or entrance motion are included. The navbar adds only the local workspace UI dependency and its navigation script.

Known sizing limitation: at a 320px viewport with 200% root text, the existing rem-based insets can leave no height for artist lettering. This predates the architecture refactor and is not a passing accessibility check.

Design authority and evidence: `odd/tasks/arc2026-static-grid.md`; accepted artboard: `design/arc2026-slot-grid/02-poster-grid.html`.
